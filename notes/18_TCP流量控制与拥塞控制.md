# TCP流量控制与拥塞控制

## 流量控制（接收方视角）
- 目的：防止发送方发太快，导致**接收方缓冲区溢出**
- 机制：接收方在ACK中携带**接收窗口 rwnd**，告知对方还能收多少
- 发送方的发送窗口不能超过 rwnd → **滑动窗口协议**
- 特殊情况：rwnd=0 时发送方停止发送，并定期发送**零窗口探测报文**

## 拥塞控制（网络视角）
- 目的：防止发送方发太快，导致**网络中路由器缓存溢出、丢包**
- 机制：发送方维护**拥塞窗口 cwnd**，根据网络状况动态调整
- **发送窗口 = min(rwnd, cwnd)**

## 拥塞控制四个阶段

### 1. 慢启动
- 从 cwnd = 1 MSS 开始，每收到一个ACK，cwnd 翻倍（**指数增长**）
- 达到慢启动阈值 **ssthresh** 后转入拥塞避免

### 2. 拥塞避免
- cwnd 每个RTT只增加 1 MSS（**线性增长**）
- AIMD：加法增（缓慢试探）、乘法减（出现拥塞立即减半）

### 3. 快重传
- 接收方收到乱序报文立即发冗余ACK（不等待）
- 发送方收到 **3个重复ACK**，立即重传丢失报文，**不等超时**

### 4. 快恢复
- 收到3个冗余ACK：ssthresh = cwnd/2，cwnd = ssthresh，从拥塞避免继续
- 区别于超时（认为严重拥塞）：ssthresh = cwnd/2，**cwnd = 1**，重新慢启动

## 超时处理
超时说明网络严重拥塞（报文丢失）：
- ssthresh = cwnd / 2
- cwnd = 1 MSS，重新慢启动
