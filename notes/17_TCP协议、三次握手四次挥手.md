# TCP协议、三次握手四次挥手

## 定义
TCP（Transmission Control Protocol，传输控制协议），运输层协议：
- **面向连接**：通信前需建立连接，结束后释放
- **可靠**：确认、重传、排序、去重
- **面向字节流**：应用数据看作字节流，分段传输

## TCP首部（20~60字节，无选项20字节）
- 源端口、目的端口（各2B）
- 序号 seq（4B）、确认号 ack（4B）
- 首部长度、保留、标志位：**SYN、ACK、FIN、RST、PSH、URG**
- 窗口大小（流量控制）、校验和、紧急指针、选项

## 三次握手（建立连接）
```
客户端                    服务端
  |---- SYN, seq=x ------>|
  |<-- SYN+ACK, ack=x+1, seq=y ----|
  |---- ACK, ack=y+1 ----->|
```
1. 客户端发送 SYN=1，seq=x，进入 SYN_SENT
2. 服务端回复 SYN+ACK，seq=y，ack=x+1，进入 SYN_RCVD
3. 客户端发送 ACK，ack=y+1，双方进入 ESTABLISHED

**为什么是三次**：确保双方都确认收发能力正常；防止**已失效的连接请求**突然到达服务端造成资源浪费（两次握手无法确认客户端收到服务端的seq）。

## 四次挥手（释放连接，全双工）
```
客户端                    服务端
  |---- FIN, seq=u ------->|  客户端不再发送
  |<-- ACK, ack=u+1 -------|  服务端确认，进入半关闭
  |<-- FIN, seq=w ---------|  服务端也不再有数据
  |---- ACK, ack=w+1 ----->|  客户端等待2MSL后关闭
```
1. 客户端发送 FIN，进入 FIN_WAIT_1
2. 服务端回 ACK，进入 CLOSE_WAIT；客户端进入 FIN_WAIT_2
3. 服务端数据发送完毕，发 FIN，进入 LAST_ACK
4. 客户端回 ACK，进入 TIME_WAIT，**等待 2MSL** 后关闭

**为什么是四次**：TCP全双工，两个方向要分别关闭；服务端收到FIN后可能还有数据要发，不能立即合并FIN。

## 2MSL（最长报文段寿命的2倍）
- 保证最后一个ACK能到达对方（丢失则对方重发FIN）
- 防止旧连接的残留报文干扰新连接
